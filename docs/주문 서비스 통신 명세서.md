# 서비스 통신 명세서

| 항목 | 내용                           |
| --- |------------------------------|
| 대상 서비스 | Payment, Product, Order      |
| 통신 방식 | RabbitMQ 비동기 이벤트, HTTP 동기 통신 |
| RabbitMQ 데이터 포맷 | JSON                         |
| 문서 기준일 | 2026-09-12                   |

## 1. 공통 정책

- Order 발행 이벤트 Exchange: `order.topic.exchange`
- Product 발행 이벤트 Exchange: `product.topic.exchange`
- RabbitMQ 공통 헤더는 `content_type: application/json`이며, `__TypeId__`는 각 이벤트 항목에 명시한 Payload 타입을 사용한다.

## 2. RabbitMQ 비동기 통신

### 2.1 결제 완료 후 재고 확정

| 항목 | 내용 |
| --- | --- |
| Producer / Consumer | Order / Product |
| Topic | `order.inventory.confirm` |
| Exchange | `order.topic.exchange` |
| Payload | `OrderEvent` |

`POST /internal/v1/orders/{orderId}/complete-pay`로 주문이 `PAID`로 전이된 직후, Product에 논리 선점 재고의 영구 차감을 요청한다.

```json
{
  "eventId": "a1b2c3d4-e5f6-7a8b-9c0d-1e2f3a4b5c6d",
  "routingKey": "order.inventory.confirm",
  "reservationToken": "rsv_8f7b2a1c3d4e4f5a9b1c8e7d6f5a4b3c",
  "orderId": 501,
  "memberId": 1001,
  "items": [{"productId": 10, "quantity": 2}, {"productId": 11, "quantity": 1}],
  "occurredAt": "2026-09-11T23:15:30.123456"
}
```

## 3. HTTP 동기 통신

### 3.1 논리 재고 선점

`POST /internal/v1/products/inventory/hold` (Order → Product)

```json
{
  "reservationToken": "rsv_8f7b2a1c3d4e4f5a9b1c8e7d6f5a4b3c",
  "items": [{"productId": 10, "quantity": 2}, {"productId": 11, "quantity": 1}]
}
```

성공 응답의 `data`는 `shippingFee`와 `items`를 포함한다. 각 품목은 `productId`, `dealProductId`, `skuId`, `productName`, `optionName`, `storageType`, `quantity`, `unitPrice`를 반환한다.

- `409 Conflict`: `ORD_INSUFFICIENT_STOCK`
- 호출 실패, 비어 있는 응답, 불완전한 품목: `ORD_INCOMPLETE_PRODUCT_RESPONSE`
- Order가 토큰과 15분 유효시간을 생성·소유하며 Product는 해당 토큰으로 선점 데이터를 저장한다.

### 3.2 기존 주문서 선점 해제

`POST /internal/v1/products/inventory/release` (Order → Product)

```json
{"reservationToken": "rsv_8f7b2a1c3d4e4f5a9b1c8e7d6f5a4b3c"}
```

- 성공: 공통 응답의 `data` = `null`
- `404 Not Found`: 없거나 이미 해제된 토큰
- `500 Internal Server Error`: Product 내부 오류

### 3.3 주문 취소 가능 여부

`GET /internal/v1/oms/orders/{orderId}/cancel-eligibility` (Order → OMS)

```json
{"status":"SUCCESS","data":{"status":"CANCELLABLE"},"error":null}
```

- `CANCELLABLE`일 때만 결제 취소와 재고 복구를 진행한다.
- `404 Not Found`: OMS 주문 없음
- `409 Conflict`: `ORD_CONFLICT_RELEASE_STARTED`

### 3.4 결제 취소

`POST /internal/v1/payments/{paymentId}/cancel` (Order → Payment), 요청 Body 없음

- 성공: 공통 응답의 `data` = `null`
- `404 Not Found`: 결제 원장 없음
- `409 Conflict`: 이미 취소되었거나 취소 불가능한 상태
- `502 Bad Gateway`: PG 통신 오류
- 성공 후 `order.canceled.inventory-restore`를 발행한다.

### 3.5 회원 배송지 조회

`GET /internal/v1/users/{memberId}/delivery-addresses/{addressId}` (Order → User)

```json
{
  "status": "SUCCESS",
  "data": {
    "addressId": 8, "addressName": "우리집", "recipientName": "홍길동",
    "recipientPhone": "010-1234-5678", "zipCode": "06234",
    "address": "서울특별시 강남구 테헤란로 123", "detailAddress": "101동 1001호"
  },
  "error": null
}
```

- `404 Not Found`: `ORD_NOT_FOUND_ADDRESS`
- Order는 응답의 배송지를 주문 스냅샷으로 저장한다.
- 인증 헤더는 HTTPS 대상으로만 전파한다. HTTP 대상은 내부 호스트여도 인증 헤더 없이 호출한다.

### 3.6 상품 일괄 요약 조회

`POST /internal/v1/products/batch-summary` (Order → Product)

```json
{"productIds":[10,11]}
```

응답 품목은 `productId`, `productName`, `thumbnailUrl`, `originalPrice`, `salePrice`, `storageType`을 포함한다. 요청 개수와 응답 개수가 다르거나 호출이 실패하면 `ORD_INCOMPLETE_PRODUCT_RESPONSE`를 발생시킨다.

### 3.7 배송 약속 조회

`POST /internal/v1/oms/delivery-promise` (Order → OMS)

```json
{
  "addressId": 8, "addressName": "우리집", "recipientName": "홍길동",
  "recipientPhone": "010-1234-5678", "zipCode": "06234",
  "address": "서울특별시 강남구 테헤란로 123", "detailAddress": "101동 1001호"
}
```

```json
{
  "status":"SUCCESS",
  "data": {
    "deliverable":true, "regionId":11, "deliveryType":"DAWN",
    "cutoffAt":"2026-09-11T23:00:00", "expectedDeliveryAt":"2026-09-12T07:00:00"
  },
  "error":null
}
```

`deliverable=false`이거나 배송 불가 권역이면 `ORD_NOT_FOUND_ADDRESS`를 발생시킨다.

### 3.8 결제 검증용 주문 조회

`GET /internal/v1/orders/{orderId}` (Payment → Order)

```json
{
  "status":"SUCCESS",
  "data": {
    "orderId":501, "orderNo":"O3D4E5F6A7B89C0D1E2F", "memberId":1001,
    "orderStatus":"PENDING_PAYMENT", "paymentAmount":41000,
    "inventoryReservedUntil":"2026-09-11T23:26:40", "remainingTimeoutSeconds":285
  },
  "error":null
}
```

- `404 Not Found`: `ORD_NOT_FOUND_ORDER`
- `remainingTimeoutSeconds <= 0`이면 Payment가 결제창 진입을 차단한다.

### 3.9 재고 확정용 주문 품목 조회

`GET /internal/v1/orders/{orderId}/items` (Product → Order)

```json
{
  "status":"SUCCESS",
  "data": {
    "orderId":501,
    "items":[
      {"orderItemId":2001,"productId":10,"dealProductId":101,"skuId":1001,"quantity":2},
      {"orderItemId":2002,"productId":11,"dealProductId":102,"skuId":1101,"quantity":1}
    ]
  },
  "error":null
}
```

`404 Not Found`이면 `ORD_NOT_FOUND_ORDER`를 반환하며, WMS 전표 생성과 FEFO LOT 할당의 기초 데이터로 사용한다.

### 3.10 결제 완료 확정 통보

`POST /internal/v1/orders/{orderId}/complete-pay` (Payment → Order)

```json
{"paymentId":9001,"paymentAmount":41000,"paidAt":"2026-09-11T23:22:00"}
```

```json
{
  "status":"SUCCESS", "message":"주문 결제 확정 성공",
  "data":{"orderId":501,"orderStatus":"PAID","paymentId":9001,"paidAt":"2026-09-11T23:22:00"},
  "error":null
}
```

- `400 Bad Request`: `ORD_INVALID_PAYMENT_AMOUNT`
- `404 Not Found`: `ORD_NOT_FOUND_ORDER`
- `409 Conflict`: `ORD_CONFLICT_ALREADY_PAID`
- `409 Conflict`: `ORD_EXPIRED_PAYMENT_TIMEOUT`
- 성공 시 `order.inventory.confirm`과 `sales.order.created`를 발행한다. 타임아웃 충돌 시 Payment는 PG 보상 취소를 수행한다.

## 4. 공통 HTTP 응답 형식

```json
{
  "status": "SUCCESS",
  "message": "요청에 성공하였습니다.",
  "data": {},
  "error": null,
  "timestamp": "2026-09-11T23:21:40Z"
}
```

`data`의 구조는 각 통신 항목을 따르며, 실패 시 `status`, `error`, HTTP 상태 코드를 함께 검증한다.
