# 서비스 통신 명세서

| 항목 | 내용                           |
| --- |------------------------------|
| 대상 서비스 | Payment, Product, Order, OMS, WMS|
| 통신 방식 | RabbitMQ 비동기 이벤트, HTTP 동기 통신 |
| RabbitMQ 데이터 포맷 | JSON                         |
| 문서 기준일 | 2026-09-23                   |

## 1. 공통 정책

- Order 발행 이벤트 Exchange: `order.topic.exchange`
- Product 발행 이벤트 Exchange: `product.topic.exchange`
- RabbitMQ 본문은 JSON이다. Topic은 라우팅 키이며 본문 필드에 포함되지 않는다.

## 2. RabbitMQ 비동기 통신

### 2.1 결제 완료 후 재고 확정

| 항목 | 내용 |
| --- | --- |
| Producer / Consumer | Order / Product |
| Topic | `order.inventory.confirm` |
| Exchange | `order.topic.exchange` |
| Payload | `OrderInventoryConfirmEvent` |

`POST /internal/v1/orders/{orderId}/complete-pay`로 주문이 `PAID`로 전이된 직후, Product에 논리 선점 재고의 영구 차감을 요청한다.

```json
{
  "eventId": "a1b2c3d4-e5f6-7a8b-9c0d-1e2f3a4b5c6d",
  "reservationToken": "rsv_8f7b2a1c3d4e4f5a9b1c8e7d6f5a4b3c",
  "orderId": 501,
  "memberId": 1001,
  "items": [{"productId": 10, "quantity": 2}, {"productId": 11, "quantity": 1}],
  "occurredAt": "2026-09-11T23:15:30.123456"
}
```

```json
  "orderId": 501,

  "items": [{"productId": 10, "quantity": 2}, {"productId": 11, "quantity": 1}],
  "occurredAt": "2026-09-11T23:20:00.654321"
}
```

### 2.4 반품 접수 통보

| 항목 | 내용 |
| --- | --- |
| Producer / Consumer | Order / OMS, Payment |
| Topic | `order.return-requested` |
| Exchange | `order.topic.exchange` |
| Payload | `OrderReturnRequestedEvent` |

배송 완료 주문이 `RETURN_REQUESTED`로 전이된 직후 OMS의 반품 접수를 위해 발행한다.

```json
{
  "eventId": "b9a8c7d6-e5f4-3a2b-1c0d-9e8f7a6b5c4d",
  "orderId": 501,
  "memberId": 1001,
  "occurredAt": "2026-09-11T23:30:00.789101"
}
```
### 2.5 재고 복원 완료 통보

| 항목 | 내용 |
| --- | --- |
| Producer / Consumer | Product / Order |
| Topic | `product.inventory.restored` |
| Exchange / Queue | `product.topic.exchange` / `order.inventory-restored.queue` |
| Payload | `ProductInventoryRestoredEvent` |

Product가 재고 복구를 시도한 뒤 처리 결과를 통보한다. Order는 `reservationToken`이 해당 주문의 선점 토큰과 일치하고 `status`가 `RESTORED`일 때만 `CANCEL_PROCESSING`을 `CANCELLED`로 전이한다. `ALREADY_RESTORED` 등 다른 결과는 최종 취소로 처리하지 않는다.

```json
{
  "eventId": "e7b8c9d0-1a2b-3c4d-5e6f-7a8b9c0d1e2f",
  "routingKey": "product.inventory.restored",
  "reservationToken": "rsv_8f7b2a1c3d4e4f5a9b1c8e7d6f5a4b3c",
  "orderId": 501,
  "status": "RESTORED",
  "restoredAt": "2026-09-11T23:25:12.123456"
}
```

### 2.7 OMS 반품 아이템 검수 요청

| 항목 | 내용 |
| --- | --- |
| Producer / Consumer | OMS / WMS |
| Topic | `oms.return.inspection-requested` |
| Exchange | `oms.topic.exchange` |
| Payload | `OmsReturnInspectionRequestedEvent` |

반품에 상온 아이템이 있으면 해당 품목의 WMS 검수를 요청한다.

```json
{"eventId":"d1e2f3a4-b5c6-7d8e-9f0a-1b2c3d4e5f6a","omsOrderId":801,"orderId":501,"omsOrderItemIds":[2001],"occurredAt":"2026-09-11T23:30:00"}
```

### 2.8 OMS 반품 주문 환불 요청

| 항목 | 내용 |
| --- | --- |
| Producer / Consumer | OMS / Payment |
| Topic | `oms.order-refund.requested` |
| Exchange | `oms.topic.exchange` |
| Payload | `OmsRefundRequestedEvent` |

냉장·냉동 아이템만 있으면 관리자 승인 시, 상온 아이템이 있으면 WMS 검수 결과 수신 시 전체 환불 요청을 한 번 발행한다. OMS가 환불 금액과 공제 수수료를 산정한다.

```json
{"eventId":"d1e2f3a4-b5c6-7d8e-9f0a-1b2c3d4e5f6a","omsOrderId":801,"orderId":501,"refundAmount":41000,"deductedFee":0,"omsOrderItemIds":[2001],"occurredAt":"2026-09-11T23:35:00"}
```

### 2.9 WMS 반품 주문 검수 완료

| 항목 | 내용 |
| --- | --- |
| Producer / Consumer | WMS / OMS |
| Topic | `wms.return.inspected` |
| Exchange | `wms.topic.exchange` |
| Payload | `WmsReturnInspectedMessage` |

상온 아이템 검수가 끝나면 발행한다. `omsOrderId`와 `omsReturnId`는 1:1 관계이며 OMS는 승인·거절 품목 ID로 결과를 판별한다.

```json
{"eventId":"d1e2f3a4-b5c6-7d8e-9f0a-1b2c3d4e5f6a","omsReturnId":701,"omsOrderId":801,"inspectionResult":"PASSED","faultType":"SELLER","approvedItemIds":[2001],"rejectedItemIds":[],"wmsNote":"검수 완료","inspectedAt":"2026-09-11T23:40:00"}
```

### 2.10 환불 완료 통보

| 항목 | 내용 |
| --- | --- |
| Producer / Consumer | Payment / OMS |
| Topic | `payment.refund.completed` |
| Exchange | `payment.topic.exchange` |
| Payload | `PaymentRefundCompletedMessage` |

Payment가 환불 결과를 통보하며 `refundAmount`는 OMS의 검증에 사용한다. `refundAt`은 Unix epoch 밀리초 값이다.

```json
{"eventId":"d1e2f3a4-b5c6-7d8e-9f0a-1b2c3d4e5f6a","omsReturnId":701,"refundAmount":41000,"refundAt":1790000000000}
```

## 3. HTTP 동기 통신

### 3.1 논리 재고 선점

`POST /internal/v1/products/inventory/hold` (Order → Product)

```json
{
  "reservationToken": "rsv_8f7b2a1c3d4e4f5a9b1c8e7d6f5a4b3c",
  "items": [{"productId": 10, "quantity": 2}, {"productId": 11, "quantity": 1}]
}
```

성공 응답의 `data`는 `shippingFee`와 `items`를 포함한다. 각 품목은 `productId`, `dealProductId`, `skuId`, `productName`, `optionName`, `storageType`, `quantity`, `unitPrice`를 반환한다.

- `409 Conflict`: `ORD_INSUFFICIENT_STOCK`
- 호출 실패, 비어 있는 응답, 불완전한 품목: `ORD_INCOMPLETE_PRODUCT_RESPONSE`
- Order가 토큰과 15분 유효시간을 생성·소유하며 Product는 해당 토큰으로 선점 데이터를 저장한다.

### 3.2 기존 주문서 선점 해제

`POST /internal/v1/products/inventory/release` (Order → Product)

- Product API는 `@Authenticated`로 보호된다. `/checkout` 요청의 JWT를 이 내부 호출에 그대로 전달한다. 단, 토큰의 평문 노출을 막기 위해 Product 대상 URL이 HTTPS일 때만 `Authorization` 헤더를 전파한다. HTTP 설정에서는 인증 헤더 없이 호출되므로 실제 연동 환경은 `services.product.base-url`을 HTTPS로 설정해야 한다.

```json
{"reservationToken": "rsv_8f7b2a1c3d4e4f5a9b1c8e7d6f5a4b3c"}
```

- 성공: 공통 응답의 `data` = `null`
- `404 Not Found`: 없거나 이미 해제된 토큰
- `500 Internal Server Error`: Product 내부 오류

### 3.3 주문 취소 가능 여부

`GET /internal/v1/oms/orders/{orderId}/cancel-eligibility` (Order → OMS)

```json
{"status":"SUCCESS","data":{"status":"CANCELLABLE"},"error":null}
```

- `CANCELLABLE`일 때만 결제 취소와 재고 복구를 진행한다.
- `404 Not Found`: OMS 주문 없음
- `409 Conflict`: `ORD_CONFLICT_RELEASE_STARTED`

### 3.4 결제 취소

`POST /internal/v1/payments/{paymentId}/cancel` (Order → Payment), 요청 Body 없음

- 성공: 공통 응답의 `data` = `null`
- `404 Not Found`: 결제 원장 없음
- `409 Conflict`: 이미 취소되었거나 취소 불가능한 상태
- `502 Bad Gateway`: PG 통신 오류
- 성공 후 `order.inventory.restore`를 발행한다.

### 3.5 회원 배송지 조회

`GET /internal/v1/users/{memberId}/delivery-addresses/{addressId}` (Order → User)

```json
{
  "status": "SUCCESS",
  "data": {
    "addressId": 8, "addressName": "우리집", "recipientName": "홍길동",
    "recipientPhone": "010-1234-5678", "zipCode": "06234",
    "address": "서울특별시 강남구 테헤란로 123", "detailAddress": "101동 1001호"
  },
  "error": null
}
```

- `404 Not Found`: `ORD_NOT_FOUND_ADDRESS`
- Order는 응답의 배송지를 주문 스냅샷으로 저장한다.
- 인증 헤더는 HTTPS 대상으로만 전파한다. HTTP 대상은 내부 호스트여도 인증 헤더 없이 호출한다.

### 3.6 상품 일괄 요약 조회

`POST /internal/v1/products/batch-summary` (Order → Product)

```json
{"productIds":[10,11]}
```

응답 품목은 `productId`, `productName`, `thumbnailUrl`, `originalPrice`, `salePrice`, `storageType`을 포함한다. 요청 개수와 응답 개수가 다르거나 호출이 실패하면 `ORD_INCOMPLETE_PRODUCT_RESPONSE`를 발생시킨다.

### 3.7 배송 약속 조회

`POST /internal/v1/oms/delivery-promise` (Order → OMS)

```json
{
  "addressId": 8, "addressName": "우리집", "recipientName": "홍길동",
  "recipientPhone": "010-1234-5678", "zipCode": "06234",
  "address": "서울특별시 강남구 테헤란로 123", "detailAddress": "101동 1001호"
}
```

```json
{
  "status":"SUCCESS",
  "data": {
    "deliverable":true, "regionId":11, "deliveryType":"DAWN",
    "cutoffAt":"2026-09-11T23:00:00", "expectedDeliveryAt":"2026-09-23T07:00:00"
  },
  "error":null
}
```

`deliverable=false`이거나 배송 불가 권역이면 `ORD_NOT_FOUND_ADDRESS`를 발생시킨다.

### 3.8 결제 검증용 주문 조회

`GET /internal/v1/orders/{orderId}` (Payment → Order)

```json
{
  "status":"SUCCESS",
  "data": {
    "orderId":501, "orderNo":"O3D4E5F6A7B89C0D1E2F", "memberId":1001,
    "orderStatus":"PENDING_PAYMENT", "paymentAmount":41000,
    "inventoryReservedUntil":"2026-09-11T23:26:40", "remainingTimeoutSeconds":285
  },
  "error":null
}
```

- `404 Not Found`: `ORD_NOT_FOUND_ORDER`
- `remainingTimeoutSeconds <= 0`이면 Payment가 결제창 진입을 차단한다.

### 3.9 재고 확정용 주문 품목 조회

`GET /internal/v1/orders/{orderId}/items` (Product → Order)

```json
{
  "status":"SUCCESS",
  "data": {
    "orderId":501,
    "items":[
      {"orderItemId":2001,"productId":10,"dealProductId":101,"skuId":1001,"quantity":2},
      {"orderItemId":2002,"productId":11,"dealProductId":102,"skuId":1101,"quantity":1}
    ]
  },
  "error":null
}
```

`404 Not Found`이면 `ORD_NOT_FOUND_ORDER`를 반환하며, WMS 전표 생성과 FEFO LOT 할당의 기초 데이터로 사용한다.

### 3.10 결제 완료 확정 통보

`POST /internal/v1/orders/{orderId}/complete-pay` (Payment → Order)

```json
{"paymentId":9001,"paymentAmount":41000,"paidAt":"2026-09-11T23:22:00"}
```

```json
{
  "status":"SUCCESS", "message":"주문 결제 확정 성공",
  "data":{"orderId":501,"orderStatus":"PAID","paymentId":9001,"paidAt":"2026-09-11T23:22:00"},
  "error":null
}
```

- `400 Bad Request`: `ORD_INVALID_PAYMENT_AMOUNT`
- `404 Not Found`: `ORD_NOT_FOUND_ORDER`
- `409 Conflict`: `ORD_CONFLICT_ALREADY_PROCESSED`
- `409 Conflict`: `ORD_EXPIRED_PAYMENT_TIMEOUT`
- 성공 시 `order.inventory.confirm`과 `order.payment.completed`를 발행한다. 타임아웃 충돌 시 Payment는 PG 보상 취소를 수행한다.

## 4. 공통 HTTP 응답 형식

```json
{
  "status": "SUCCESS",
  "message": "요청에 성공하였습니다.",
  "data": {},
  "error": null,
  "timestamp": "2026-09-11T23:21:40Z"
}
```

`data`의 구조는 각 통신 항목을 따르며, 실패 시 `status`, `error`, HTTP 상태 코드를 함께 검증한다.
