# 보안 정책 가이드 — 로깅·패치·계정관리 (2026-09-09)

| 항목 | 내용 |
| --- | --- |
| 작성 | 보안팀 |
| 전달 대상 | 인프라팀, 개발팀(BE) |
| 성격 | 보안팀이 임의로 만든 기준이 아니라, **법령(개인정보의 안전성 확보조치 기준)** 및 **ISMS-P 인증기준**에서 요구하는 내용을 정리한 것입니다. 아래 요건을 반영해 각 팀에서 정책/설정을 수립·이행해 주세요. |
| 확인 방식 | 보안팀은 1차 점검 시 "이 요건대로 되어 있는지"만 확인합니다. 정책 자체의 세부 수립은 각 팀 재량입니다(단, 아래 필수 요소는 반드시 포함되어야 함). |

---

## 1. 로그 관리 (서버·DBMS 공통)

**근거**: 「개인정보의 안전성 확보조치 기준」제8조(접속기록의 보관 및 점검)

### 필수 요건

| 항목 | 요건 |
| --- | --- |
| 보관기간 | **1년 이상**. 단, 아래 중 하나라도 해당하면 **2년 이상**: ① 5만명 이상 정보주체 처리 ② 고유식별정보·민감정보 처리 ③ 기간통신사업자(전기통신사업법 제6조제1항) |
| 점검 주기·방법 | 법에서 특정 횟수를 강제하지 않으며, **조직이 내부적으로 정해 이행**하면 됩니다. 보안팀 제안: **월 1회 이상** (특별한 이견 없으면 이 기준으로 진행) |
| 안전한 보관 | 접속기록이 위·변조·도난·분실되지 않도록 보호 조치 필요 |
| 점검 대상 | 개인정보처리시스템에 접속한 자(정보주체 본인 제외) — 서버 접속기록(SSM 세션 로그 등), DB 접속기록 모두 포함 |

### 적용 범위
- **서버**: OS 레벨 로그(SSM 세션 로그, sudo 실행 로그, 인증 로그) — **인프라팀**
- **DBMS**: DB 접속·쿼리 실행 기록 — 담당 확인 필요(인프라팀 또는 BE/플랫폼팀, K8s 오퍼레이터 기반 운영이라 확인 필요)

## 2. 패치 관리 (서버 OS + 컨테이너 이미지)

**근거**: ISMS-P 인증기준 2.10.8(패치관리) + 2.11.2(취약점 점검 및 조치)

### 필수 요건 (숫자가 아니라 "포함되어야 할 요소")

| 요소 | 요건 |
| --- | --- |
| 대상 목록 관리 | 서버·네트워크·DBMS·애플리케이션 등 자산별로 OS·소프트웨어 버전, 패치 적용현황, 적용일자를 목록으로 관리 |
| 패치 주기 | 자산 중요도에 따라 조직이 자율적으로 정함(법정 고정값 없음) |
| 영향도 분석 | 운영 시스템에 패치 적용 시 가용성 영향을 사전 분석하는 절차 필요 |
| 보완대책 | 서비스 영향으로 최신 패치 적용이 어려운 경우, 즉시 적용 대신 **보완대책**을 마련하고 문서화 |
| 취약점 점검 | 정기적 취약점 점검(통상 연 1회 이상) + 점검 이력 관리 + 재발 방지 |
| 패치관리시스템 보호 | 패치관리시스템 자체에 대한 접근통제(허가된 관리자 외 접근 차단 등) |

### 적용 범위
- **OS 패치**: 서버(워커노드, NAT Instance) — **인프라팀**
- **컨테이너 이미지 패치**: 애플리케이션 이미지 — **개발팀(BE)**

## 3. IAM/계정 관리 (클라우드)

**근거**: ISMS-P 인증기준 2.5.2(사용자 식별), 2.5.5(특수 계정 및 권한 관리)

### 필수 요건

| 항목 | 요건 |
| --- | --- |
| 관리자 계정 수 | **최소 인원**에게만 부여(법정 고정 인원수는 없음 — 조직이 업무상 필요 최소 범위로 판단) |
| 계정 식별자 | **root, admin, administrator 등 추측하기 쉬운 이름 사용 제한**. 1인 1계정 원칙 |
| 공용계정 | 불가피하게 필요한 경우 사유·타당성 검토 → 책임자 승인 → 책임추적성 확보 대책(예: 개인 계정 로그인 후 관리자 계정 전환) 필요 |
| 특수권한(Admin Console 등) 부여 | 공식적인 신청·승인 절차 필요(일반 계정보다 엄격한 기준, 임원/보안책임자 승인 등) |
| 특수권한 통제 | 별도 목록 관리, 예외조치 최소화, 모니터링 강화, 정기적 재검토 |

### 적용 범위
- AWS IAM 사용자 계정, Admin Console 접근 — **인프라팀**

## 참고 — 이 가이드에 없는 항목

- **3.10(ELB 제어정책)**: 법적/인증 근거를 찾지 못해 이 가이드에는 포함하지 않았습니다. 인프라팀과 별도 협의로 진행 중입니다.
- **D-03(DBMS 비밀번호 정책), D-05(재사용 제한)**: 법적으로 구체 수치를 강제하는 근거가 없어, 이 가이드에는 포함하지 않았습니다. 대신 DBMS 담당팀(인프라팀 또는 BE)이 만료일수·복잡도·재사용 제한 횟수를 직접 정해서 알려주시면, 보안팀은 그 값을 기준으로 검증만 진행합니다. (「기준값 확인요청 노션표」에서 요청 예정)
- 위 요건들은 최소 기준입니다. 각 팀에서 이보다 강화된 기준을 적용하는 것은 무방합니다.
